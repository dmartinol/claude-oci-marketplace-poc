A practical supply chain

From a plugin folder to a controlled update

Agent skills and plugins are software artifacts. The PoC connects familiar software delivery steps to the AI assets a team installs in Claude Code.

01

Build the asset

Keep the plugin manifest and its skills together as one complete directory.

.claude-plugin/plugin.jsonskills/demo/SKILL.md
02

Validate and publish

Run Claude's strict plugin validation, then publish the directory to an OCI registry with ORAS.

claude plugin validate --strict .oras push … .
03

Register and install

A GitHub marketplace points to the OCI tag. The manager resolves it, checks the bundle, and prepares a native-compatible marketplace.

marketplace source → OCI tagOCI tag → sha256 digest
04

Review updates

Metadata checks notice a changed digest. The user reviews the version and approves before the replacement is downloaded and activated.

inspect → review → approverestart to activate
↳ Claude Code stays the user-facing install and permission surface; the manager automates the OCI handoff and update checks.

What this adds to the chain

Make package delivery repeatable and inspectable.

The point is to give teams a controlled route for getting AI assets from a maintainer to a user's agent, using the same kind of identity, validation, and release discipline used for other software.

01

Package checks before use

Validate the plugin layout and ensure the package identity and version agree with the OCI metadata.

02

Know which bytes were reviewed

Resolve mutable tags to a SHA-256 digest and retrieve the exact digest selected for installation or update.

03

Put a person at the release gate

Show an update notice and require confirmation plus Claude's permission approval before downloading a replacement.

04

Keep the known working version

Stage and validate replacements first. A retrieval, validation, or activation failure preserves the prior plugin.

Scope of the claim

Package validation is a useful control, not a safety verdict.

This PoC checks Claude plugin structure, metadata consistency, and the identity of the OCI bytes being installed. It does not evaluate whether a skill's instructions are safe or correct, verify publisher signatures or build provenance, scan dependencies, or certify behavior. Signing, provenance attestations, policy checks, and content evaluation would add further supply-chain controls.

Current scope

A working Claude Code integration for OCI-distributed plugins.

The bundle format, registry declaration, and manager experience in this PoC are Claude-specific. The example skill is portable content, while broader agent interoperability would need a shared package and catalog contract plus client adapters.
