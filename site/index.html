Your workflow

Package, publish, install, update

Package one complete Claude plugin and point a Git marketplace to its OCI tag. Add the marketplace in Claude Code, then install and update through /plugin or the manager.

01

Prepare your plugin

Keep the plugin manifest and its skills together in one directory.

.claude-plugin/plugin.jsonskills/demo/SKILL.md
02

Validate and publish

Check the plugin with Claude's validator, then publish the directory to an OCI registry with ORAS.

claude plugin validate --strict .oras push … .
03

Add the marketplace

Run /marketplace-manager add <git-url>. Approve the download; the manager validates the bundle and registers a marketplace Claude Code can use.

marketplace source → OCI tagOCI tag → sha256 digest
04

Install and update

Install from /plugin or the manager. When the tag points to a new digest, approve the download, then restart Claude Code to use the update.

check → approve → downloadrestart to use the update
↳ Refresh at startup or on demand, or set automatic checks to every five minutes (one minute for demos). The manager checks registry metadata only and stops when your Claude Code session ends.

Your controls

See what you install. Approve what changes.

Check the plugin package, see the source reference and exact digest, and approve downloads before Claude Code uses a new version.

01

Check the plugin package

Validate its layout and confirm the plugin name and version match the OCI metadata.

02

Know which bytes you selected

Resolve a mutable tag to a SHA-256 digest. Download that exact digest after approval.

03

Approve each change

Select the plugins to update and confirm before downloads start. Claude Code also asks for permission.

04

Keep your working version

The manager stages and validates a replacement first. If retrieval or activation fails, your previous plugin remains usable.

Know what these checks cover

Check the package and exact digest.

A digest identifies the bytes you install; it does not authenticate the publisher. This demo checks plugin structure and metadata. It does not verify signatures or build provenance, scan dependencies or advisories, assess whether instructions are safe or correct, or certify behavior at runtime. Use those as separate checks when your supply-chain policy requires them.
